5. 关键流程

daemon 启动

  1. 验证 profile，取得排他生命周期租约；vault 文件锁等待最多 30 秒。
  2. 读取当前 protocol-v3 hashed 运行锁；只有在排他租约下安全删除畸形的当前 v3 候选并重读后得到 Removed/Absent，才可继续。Changed/Contended、Unix raw legacy 和旧/未知协议都 fail closed。
  3. 解密 v2 profile；首次连接先 KEX/观测 host key，在排他租约下原子写 pin，只有写入成功后才发 SSH 密码。迟到 pin 可能持久化，但不会认证已过期 transport。
  4. UI 从最初 status probe 起使用单一 30 秒 absolute deadline。listener bind 与 lock publication 在 owned blocking worker 内完成；原子写锁前就 arm token-CAS cleanup guard，并持有排他租约。
  5. readiness 通过 oneshot 交接所有权；receiver 消失会 invalidate SSH 并清理已发布 runtime。ready 与 daemon ended 同时发生时偏向先发 Started。成功后进入 64 连接/8 重结果槽 accept loop。

IPC v3 互认证

  1. 客户端从受保护锁读取 PID、endpoint 和随机秘密，验证 endpoint 派生值。
  2. 连接后、发送认证帧前核对 OS 对端 PID/UID。
  3. 交换 AuthHello、AuthChallenge、AuthResponse；daemon 与 client 分别证明持有共享秘密。
  4. 只有互认证成功后才接受业务帧；失败直接关闭，不向未认证 peer 返回结构化错误 oracle。

exec

  1. 校验命令不含 NUL 且不超过 64 KiB，建立 absolute deadline并只路由一次。
  2. deadline 覆盖 IPC、重结果槽等待、单飞重连、DNS/TCP/KEX/auth、channel open、exec request、输出与退出状态。
  3. IPC writer 在每次 poll_write 与 poll_flush 前都检查同一 absolute deadline，避免外层 timeout 对 ready inner Future 的最后一次 poll 越过预算。只有 4 字节长度头和完整序列化 payload 都被 AsyncWrite 成功接收后、flush 前才跨过提交边界。序列化失败、零字节/部分帧写失败和完整帧前 deadline 都是确定的 pre-submit；完整帧后的 flush/响应失败、deadline 或断开属于 typed ExecOutcomeUnknown。
  4. v3 daemon 的普通 Error 只表示已确认尚未把请求交给 russh，post-submit 错误必须编码为 typed unknown；v3 client 因此拒绝 protocol 2 锁与 v2 challenge，避免把旧 v2 的无标记 post-submit Error 误当作“确定未执行”。
  5. 直连 russh 的 bounded exec-send 在每一次 poll 前检查 absolute deadline，只有内部请求成功入队才跨提交边界；Pending 不能越过预算后再触发远端执行。只接受明确且唯一的 ExitStatus，无退出码、重复退出码和输出超 8 MiB均失败且在已提交后属于结果未知。
  6. 异常退出依次有界尝试 TERM、短宽限、KILL、EOF、Close 和关闭确认；不能确认时使 transport 失效。

创建目录

  1. IPC 请求沿用完整 frame 提交边界；direct SFTP MKDIR 从第一次实际 poll 起记录 request may have reached remote。两条路径都在每次 mutation poll 前检查 absolute deadline。
  2. 显式且请求 ID 匹配的 SFTP STATUS 拒绝，以及 daemon 在 validation/session setup 或该显式 STATUS 后返回的普通 Error，是明确未创建的 plain rejection。
  3. 请求可能已到达后若 deadline、EOF、unexpected response 或 transport/protocol 错误阻止确认，则返回 typed CreateDirOutcomeUnknown，使旧 transport 失效，并要求检查远端路径后再重试。

上传

  1. 在任何路由/SSH 之前只打开一次本地普通文件，保留稳定 handle 与 size。
  2. 远端同目录以 CREATE | EXCLUDE 和 0600 创建随机 partial；CREATE 首次被 poll 后即保守记录 partial 可能存在，只有显式且匹配请求的 SFTP STATUS 拒绝能证明未创建。其他 deadline/断开/协议错误继续进入清理。
  3. partial CREATE、逐块 WRITE、flush、shutdown、hardlink/rename commit 与 unlink cleanup 的 Future 均在每次 poll 前检查对应 absolute deadline，防止 Pending 在预算之后才产生副作用。
  4. 优先 hardlink@openssh.com no-replace commit；未声明扩展时才走标准 SFTP v3 RENAME fallback。
  5. commit 确认后即使临时名删除被打断也报告已提交；UploadEnd 周围的响应丢失有 2.25 秒对账，否则返回 typed UploadCommitOutcomeUnknown。
  6. 直连上传的 owned worker 在外层 Future timeout/drop 后继续拥有 fresh-channel 清理；commit 已开始后的 Finished(Err) 也是 outcome unknown，不是确定未提交。

下载

  1. 受保护 CREATE_NEW 一成功就立即 arm CreatedFileRollback，再验证 owner/type/ACL；错误或 panic 只删除稳定身份确认的新对象。
  2. 读取远端内容、核对字节数、flush、sync_all。
  3. 同目录 hard link 原子安装最终名；已存在时不覆盖，并以稳定 handle 对账最终对象身份。
  4. 本地 partial create 在 owned blocking worker 内返回 UnclaimedLocalPartial；未 claim 结果在 cancel/timeout/drop/unwind 下仍由 Drop 调度清理，claim 交接中间无 await。

交互 shell

PTY 列数和行数由 direct、IPC client 与 daemon 统一限制为 1..=10000，非法尺寸在 I/O 前拒绝。直连 SSH+PTY setup 共用 30 秒 deadline；IPC client 的 Shell/Ack 上限为 32 秒，daemon 内部仍为 30 秒。client/daemon 在整个 IPC shell 中各自保留一个 pinned frame decoder，避免 cancel/drop 卡在 header/body 中间时丢失 framing；等待满队列和已入队的 channel element 都有 RAII zeroize envelope。CLI stdin 以 100 ms crossterm::poll 响应取消，忽略 key release，接受 press/repeat；raw mode 由 RAII guard 持有，正常返回、错误、任务 abort 或 unwind 都会尝试恢复终端。setup 成功后的会话没有整体 deadline。

7. Winit/Egui 桌面 UI

  • 目录、文件传输、命令与 Bash 交互均通过后台 Tokio runtime 执行。profile refresh 在 UI 调用时只建立一个 32 秒 absolute deadline，覆盖 spawn_blocking vault list/KDF 和分波的最多 8 个 daemon status probe；未启动波次被取消。运行中的 blocking job 可迟到，但其 SensitiveProfileListResult 由 RAII 清零，不占住 Tokio worker。
  • profile epoch、目录 generation 与 daemon instance id 进入异步结果身份；切换、编辑、删除或重启 profile 后，旧 worker 的迟到响应不能覆盖新状态。
  • 保存成功消息携带原 profile 名；reducer 在发起 refresh 前先清零并删除原名和新名两侧的缓存行，同时失效当前 profile context、目录、命令输出和 shell。因而 H1 以同名覆盖为 H2 后，即使 refresh 失败，旧 H1 状态也不再可操作。
  • workspace master、editor SSH password 和 editor master 由 MaskedSecretTextBuffer 编辑；egui 只看到等 Unicode 字符数的 *。每次 show 前后都将 undo max_undos=0，Unicode 编辑替换的旧 app string 会清零。eframe persistence feature 已移除，persist_egui_memory/persist_window 均为 false。
  • SensitiveUiMessage envelope 从队列、send 失败、receiver drop 一直持有到 reducer match 完成；unwind 会清零 payload 并取消 GuiShell。CommandOutput::drop 清零，command/PTY lossy 转换中间缓冲为 Zeroizing。
  • runtime 是独占 Option<Runtime>。正常 on_exit 先 cancel transfer，最多 6 秒协作等待并 abort 超界任务，再并发 down UI-owned daemons，最后 shutdown_timeout(1 s)。panic/未调用 on_exit 只能 cancel + shutdown_background，不保证 async cleanup 完成。
UI P3 边界：非凭证的 command/shell/path/output 仍可在 egui、字体布局、IME、OS 与 allocator 内形成普通临时副本。稳定 widget ID 和每帧清 undo 只是缩小暴露，不是完整内存清零。

  • v2 profile 的 endpoint 元数据受认证。磁盘 format 字节不在 AAD 内，因此显式离线替换会先按 no-AAD legacy decrypt 验证真正旧记录，且不继承旧 host-key pin；翻转现代记录 format 2→0 会因 tag/decrypt 失败，不能擦 pin 或重开 TOFU。
  • 密钥派生通过 hash_password_into_with_memory 直接写入精确的 Zeroizing<Vec<Argon2Block>>；64 MiB 矩阵由 RAII 擦除，Argon2 内部 initial/block hash 的可控副本由开启的 zeroize feature 覆盖。
  • 密码校验、profile 加解密、vault 更新和运行锁写入的敏感 JSON使用两遍序列化：第一遍仅计数，第二遍写入精确预分配的 Zeroizing<Vec<u8>>。IPC frame 同样不先生成普通敏感 Vec。
  • 可控明文、命令、帧、输出和缓冲在 Drop/错误路径清零；这不能清除 allocator、OS cache、第三方库、swap 或 crash dump 中的副本。
  • vault 更新和运行锁发布共用同目录受保护原子替换；vault 文件锁采用 try_lock 轮询且最多等待 30 秒。Unix 同步临时文件后原子 rename，再 fsync 父目录；Windows 从临时文件创建时即施加 protected DACL，sync_all 后持有稳定、已验证的受保护父目录句柄，并调用 Microsoft MoveFileExW（MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH）。
  • 注入提交失败会保留旧目标并清理临时文件；Windows 本机测试还核对成功内容与 DACL。该证据验证 API 的写穿/同步路径和故障保持性，不是实际断电模拟，也不把 OS、文件系统或硬件之外的持久性当作已证明。

稳定句柄与平台权限

  • Unix：安全目录/文件以 O_NOFOLLOW | O_NONBLOCK 打开，在相同 handle 上验证 regular/type、effective UID和 0700/0600。
  • Windows：目录/文件拒绝 reparse，并使用禁止继承的 owner/SYSTEM/Administrators protected DACL；失败关闭。对象 owner 必须匹配当前进程令牌的 TokenUser 或 TokenOwner。后者兼容提升令牌以 BUILTIN\Administrators 作为默认 owner 的正常对象，同时仍拒绝与本令牌无关的 SID，不扩大 protected DACL 已明确包含的管理员边界。
  • 只读运行锁在首次读取前就建立 Zeroizing 缓冲，一次预分配 64 KiB + 1，避免增长/realloc 时释放含 token 前缀的旧 allocation；稳定 handle 上的二次上限读取阻断 metadata 后增长竞态。

租约与畸形锁恢复

daemon 生命周期和 profile 变更使用排他租约；普通直连使用共享租约。profile mutation 只有在排他锁实际返回 contention 时才显示“正在被 direct operation 或 daemon 使用”；打开 lease、owner/ACL 或其他 I/O 失败保留真实错误链，不再被一律误包装为占用。首次 TOFU 时，直连与 daemon 都先 KEX/观测 key，在排他租约下原子只写一次 pin，之后才发送 SSH password。假 server E2E 已验证 pin 写入失败时不会看到 auth request。

当前 protocol-v3 hashed 运行锁若无法解析，清理器必须先取得同一排他生命周期租约，再验证 runtime 目录及文件权限/类型并重读 namespace。对账结果只有 Removed/Absent 允许进入 direct fallback；Changed/Contended 均 fail closed。protocol 0/2 与未知版本锁在连接前拒绝且保留，不按“畸形当前锁”清理；Unix 上被遮蔽的 raw legacy 锁仍会拒绝，Windows 不探测不安全的 raw legacy 名称。

9. IPC v3：统一抽象与双向认证

传输与 OS 边界

  • Windows Named Pipe 和 Unix Domain Socket 对上层暴露同一 AsyncRead/AsyncWrite、listener、connect 与长度前缀 JSON frame API，不存在两套业务协议。
  • Windows 每一个 pipe instance（包括 accept 后预建的下一实例）都在创建时传入禁止继承、仅 owner/SYSTEM/Administrators 的 DACL，并拒绝远程客户端。
  • Unix socket 位于 0700 runtime 目录，socket mode 为 0600。
  • 认证前客户端用 GetNamedPipeServerProcessId 核对 server PID；Unix 用 peer credentials 核对当前 euid，并在平台提供 PID 时与锁中 PID 匹配。

三帧 nonce-HMAC-SHA256

client  → AuthHello(version=3, client_nonce)
daemon  → AuthChallenge(version=3, server_nonce, server_proof)
client  → AuthResponse(client_proof)

证明输入绑定独立的 server/client role 域、协议版本、profile 长度与内容、派生 endpoint id、client nonce 和 server nonce。共享秘密只作为 HMAC key，不作为帧字段发送；双方 nonce 各为 32 随机字节且不得相等。Base64 解码必须得到规范、带 padding 的恰好 32 字节值，proof 使用常量时间比较。这样可以阻止角色反射、跨 profile/endpoint 重放、降级和非规范编码混淆。

v3 切换边界：exec 的普通拒绝与 post-submit unknown 现在具有严格且受版本约束的语义，因此不与 v2 混跑。v3 client 看到 protocol 0/2 或未知锁时在 connect 前失败并保留证据；若认证流直接收到 v2 challenge，也不发送 client proof。活动旧 daemon 必须先由匹配的旧 binary 正常停止，再整体切换 client/daemon。

11. 目录浏览与传输完整性

统一 SFTP frame guard

高层 russh-sftp 和自实现目录 reader 均通过相同 bounded stream。每个 SFTP 长度前缀一到达就先检查 body 不超过 1 MiB；超限时不读取/分配声明 body，立刻标记 transport 失效并触发代理取消。SFTP init 卡住仍由外层 absolute deadline 兜底。

流式目录列表

  • 直接执行 SFTP v3 REALPATH、OPENDIR、重复 READDIR、CLOSE，不调用先聚合任意结果的便捷 API。
  • 协议 packet encoded body 累计最多 8 MiB；canonical path、name 与完整 path 的保留字符串合计最多 2 MiB；entry 最多 10,000。
  • 拒绝空名、绝对名、包含 /、.. escape 或 NUL 的 entry component。
  • 排序一次性缓存小写 key，避免比较器重复分配；最终以真实 DirList JSON 序列化大小验证 16 MiB IPC wire 上限，覆盖控制字符六倍转义最坏情形。
  • daemon 与 direct 使用同一 reader/预算；解析或预算失败会关闭 channel 并使 transport 失效，下一请求通过单飞重连恢复。

远端上传

  • 目标/临时路径长度和 NUL 被统一验证；临时名预留完整 45 字节后缀。
  • partial 使用 SFTP CREATE | EXCLUDE | WRITE，创建属性 0600，因此没有服务器默认常见 0644 的暴露窗口。CREATE 首次被 poll 后就视为可能创建；只有匹配请求的显式 SFTP STATUS 拒绝证明未创建，transport/protocol/deadline 错误必须继续清理。
  • CREATE、逐块 WRITE、flush、shutdown、hardlink、rename 与 remove-file cleanup 都通过 mutation guard，在每一次 poll 前检查所属 absolute deadline；外层 timeout 不会在截止点再 poll 一个刚变 ready 的副作用 Future。
  • 优先 OpenSSH hardlink@openssh.com。扩展被声明却报错时，不尝试 rename，以免“目标存在”被错误降级成覆盖路径。
  • 仅当扩展未声明时使用标准 SFTP v3 RENAME；v3 要求目标已存在时失败，但这是对服务端合规性的外部假设。
  • hardlink 成功即记录 committed，再尝试 unlink 本方 partial；删除失败不会把已安装目标倒退成失败。直连 worker 在 commit_started 后的 timeout/cancel 或 Finished(Err) 而未确认 committed 时，均返回 typed UploadCommitOutcomeUnknown。

本地上传源

源文件在 daemon/direct 路由和 SSH 认证前只打开一次，后续始终读取同一 handle。Unix 用 O_NONBLOCK 后 fstat 拒绝 FIFO、设备、目录，允许最终指向普通文件的 symlink；Windows 用 OPEN_REPARSE_POINT 并拒绝 reparse/设备/目录。程序不改变用户源文件 ACL。

本地下载

  • partial 以随机同目录名称和 atomic create_new 建立；创建成功一返回就 arm CreatedFileRollback，所以后续验证错误/panic 也会回滚。Unix 用 dev/inode 保留同名替换对象，Windows 用稳定 handle 删除原创建对象；碰撞不会误删。
  • Unix 从创建瞬间即 owner-only 0600，并在 handle 上核对 UID/type/mode。Windows 在 CREATE_NEW 时通过 SECURITY_ATTRIBUTES 应用 protected owner/SYSTEM/Administrators DACL，再验证 owner/DACL/reparse/type。
  • 本地 create 由 owned spawn_blocking 返回 UnclaimedLocalPartial；异步 Future 在 cancel/timeout/drop/unwind 下未 claim 时，Drop 仍会调度清理，claim 交接中间没有 await。blocking pool 饱和会延迟但不放弃清理；无法创建清理线程时可能保留路径。
  • 传输完成后 flush + sync_all，再以 hard link 原子 no-replace 安装最终名称。Windows 在 clone path/spawn 不可逆 hardlink worker 之前先复查 now < deadline，避免 elapsed deadline 下 timeout_at 仍先 poll ready inner；安装后在有界 blocking worker 内对稳定 handle 调用 GetFileInformationByHandle 对账。
  • hard link 不可用时安全失败而不是退化为可覆盖 rename；磁盘耗尽/文件系统故障也会保留明确错误。
内容级边界：当前验证字节数、权限、提交身份和 no-overwrite，不实现远端 fsync 协议或 evidence 内容签名。审计流程仍应独立计算/核对 SHA-256 或数字签名。

12. SSH 算法、存活与重连

  • 依赖 russh 0.62.5，关闭默认 feature 并只启用 ring 后端；KEX/MAC 沿用 russh 当前安全默认。
  • server host-key 签名仅允许 Ed25519、ECDSA、RSA-SHA2-256 与 RSA-SHA2-512；没有 hash 标识的 ssh-rsa SHA-1 被明确过滤。
  • SSH host key 使用 SHA-256 fingerprint。首次 TOFU 按 KEX/观测 key → 排他租约下原子 pin → 发送 password 的顺序执行；pin 失败时在 auth 前中止 transport。russh password-auth send 的 bounded Future 在每次 poll 前检查 absolute deadline，Pending 不能在预算之后才披露密码。之后所有连接/重连都要求一致。
  • TCP 经双向 copy proxy 交给 russh。deadline 或 cancel 会关闭 proxy 两端并等待退出，解决 russh 在 KEX 前已 spawn session task、丢弃 connect Future 仍可能泄漏的问题。
  • keepalive 每 30 秒发送，连续 3 次无响应后连接失效；SessionManager 通过 Mutex 单飞重连，等待锁、DNS/TCP/KEX/auth 全部消耗调用者剩余 deadline。
  • 在途请求持有旧 Arc<SshSession>；替换不会从请求下方移动对象。不可安全取消的 channel-open/SFTP-init 超时会 invalidate 整个旧 transport。
  • status 不只检查本机 IPC，还要求取得健康 SSH session/reconnect，避免报告“daemon 活着但 SSH 永久失效”的假健康。daemon 内部 control setup 上限为 30 秒，但 client 的整个 status control exchange 硬上限为 3 秒，因此外部调用由更短的 3 秒预算主导，超时后断开该 IPC。

14. 残余风险与信任边界

R1 · TOFU 首次 MITM

固有

第一次看到的 host key 会被固定；若首次链路已被中间人控制，就会固定错误指纹。高安全环境必须通过独立渠道预核对 fingerprint，或未来支持预置 known_hosts/pin。

R2 · SFTP v3 fallback 依赖服务端合规

兼容边界

OpenSSH hardlink 扩展存在时提供明确 no-replace；只有扩展未声明才使用 v3 RENAME。规范要求目标已存在时报错，但非合规服务器可能替换目标。应在目标服务器矩阵中验证，或要求 hardlink 扩展。

R3 · 本地文件系统 syscall 不可抢占

OS 边界

open、flush、sync_all、hard_link 等进入 kernel 后不能由 Tokio timeout 取消；已经启动的 blocking work 在外层 Future 超时时也可能只能 detach。owned task 与身份 reconcile 防止假成功，但病态调用可在 grace 后才改变目录。可写目录中的同用户攻击者也能持续制造 path race；这不属于不同 OS principal 的隔离。

R4 · 强杀、崩溃与 panic cleanup

协作式

正常 timeout/cancel/关闭会等待有界清理；TerminateProcess、kill -9、断电或 runtime 崩溃不会运行 async cleanup。UI Drop/panic 能发 cancel，却不能保证等待 worker。远端/本地 .serctl-part-* 仍应纳入运维扫描；原子写测试验证 OS 同步/写穿 API 与注入失败路径，并未实施真实断电试验。

R5 · 平台验证缺口

待 CI

Windows 本机覆盖原生 IPC、DACL、原子写穿成功/失败/清理；Unix 的临时文件同步、rename 和父目录 fsync 分支只有 cfg/审查证据，需 Linux/macOS runtime CI。Windows reparse 动态测试在无 symlink 权限时 skip，且未做多账户 Named Pipe/vault DACL 攻击矩阵。还需 OpenSSH/Dropbear/其他 SFTP server 的外部兼容矩阵。

R6 · 原始远端终端输出

信任输入

程序自身错误和日志会转义控制字符，但 exec/PTY 的远端输出为实现终端交互而原样发送。恶意 ANSI/OSC 可影响终端；不可信输出应重定向、下载后检查或额外转义。

R7 · 同用户/管理员与内存副本

威胁模型

owner-controlled Unix mode、owner/SYSTEM/Administrators protected DACL 与 HMAC 不防御已经取得同一用户、管理员、调试、键盘记录或内存转储能力的攻击者。Zeroizing 只能清理本程序掌控的副本，无法追溯 OS、allocator、russh/serde 内部、swap 或 crash dump。UI 的非凭证 command/shell/path/output 也可在 egui/字体/IME/OS 中留普通临时副本。

R8 · TERM/KILL 不是远端进程组保证

协议边界

channel signal、EOF/Close 和 transport invalidate 会释放本地/daemon 资源，但远端 shell 可忽略信号，或子进程已经脱离 channel。需要强任务终止时，远端命令本身应使用进程组/任务控制器和服务端 deadline。

R9 · 来源标识不是签名

供应链边界

commit + dirty 只是 build script 观察到的 Git 来源信号。仓库根不监听，新增根级 untracked 文件可能需其他输入变化才重算；ignored、外部或动态构建输入也可逸出 dirty 判定。它不是签名、制品证明或可复现构建证明；可靠回滚需 clean commit/push。

R10 · 旧 protocol 0/2 不兼容

迁移边界

v3 与旧实现使用同一 hashed .lock/.lease 文件命名，但没有 dual-stack。正在使用的旧 release 锁缺少 protocol，解析为 protocol 0/bearer IPC；开发期 protocol 2 也不兼容。v3 client 在连接前 fail closed，不发送认证字节、不删除旧锁，也不回退直连。活动旧 daemon 应用匹配旧 executable 正常 down；protocol 0/2 stale 锁只能在离线核实 PID/进程不存在、租约未持有、owner/ACL/type 安全后人工处置。

15. 运维手册

推荐流程

  1. 使用长且唯一的主口令创建 v2 profile；旧格式不要直接用于网络，使用显式离线替换。
  2. 通过独立渠道核对首次 SHA-256 host-key fingerprint，再让 TOFU pin 成为可信基线。
  3. 需要连接复用时运行 serctl up NAME；自动化前用 status 验证 daemon 与 SSH 都健康。
  4. 为 exec/传输设置符合任务 SLA 的 --timeout-secs，不要无条件使用 24 小时上限。
  5. 下载 M7 evidence 后独立计算 SHA-256/验证签名，并记录 serctl commit、remote path、时间和摘要。
  6. 升级跨 IPC 协议版本时，先用与活动旧 daemon 匹配的旧 executable 正常 down，然后整体切换 client/daemon；v3 对 protocol 0/bearer、protocol 2 与未知版本锁在连接前 fail closed，不发送认证字节、不自动删除且不静默降级。
  7. 定期扫描双方目录中的 .serctl-part-*，只在确认没有运行任务后清理。

Release 体积优化

正式 Release 采用体积优先且保持可移植性的 profile：

[profile.release]
opt-level = "s"
lto = "fat"
codegen-units = 1
panic = "unwind"
strip = "symbols"

opt-level = "s"、fat LTO、单 codegen unit 与符号剥离共同压缩交付文件。panic = "unwind" 是有意保留的安全语义：终端 raw mode 恢复、敏感缓冲清零和已创建 partial 的回滚都依赖 unwind 时执行 Drop，所以不以 panic = "abort" 换取更小体积。构建不使用 UPX，避免引入运行时解包、恶意软件误报、代码签名/扫描和故障定位方面的额外发布变量；也不使用 target-cpu=native，确保同一 Windows 架构内的 Release 不绑定构建机 CPU 指令集。

依赖侧把 Tokio 的 full feature 收窄为实际使用的 fs、io-std、io-util、macros、net、rt-multi-thread、signal、sync、time，并移除已不再需要的 async-trait 直接依赖及锁定包，避免为未使用能力保留依赖和编译输入。
