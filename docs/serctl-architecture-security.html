总体结论：当前实现已具备可用的本机认证 IPC、明确退出码语义、daemon 端命令取消、SFTP 双层 deadline、原子上传/下载、取消后残片清理、SSH keepalive 与断线重连，以及 Git commit 嵌入式来源标识。它适合受信任单用户主机上的 SSH 控制工作流，但不是针对已取得同用户权限或管理员权限攻击者的隔离边界。

5. 关键流程

daemon 启动与认证
  1. 获取按 profile 划分的 OS 级生命周期租约，防止重复 daemon。
  2. 拒绝无令牌旧锁和 loopback TCP 旧锁；对新格式锁执行带 800 ms 上限的认证探测。
  3. 解密凭证并连接 SSH；首次连接采用 TOFU，成功后只写一次固定主机指纹。
  4. 创建 256 位随机 IPC token；用 SHA-256(profile || NUL || token) 的前 128 位构造紧凑端点名。
  5. 写入受保护锁文件。锁中保留 profile、PID、端点、启动时间、token；新格式不写远端 host/user。
  6. 客户端连接后必须在 2 秒内发送不超过 4 KiB 的认证帧；令牌用常量时间比较。
远程命令
  1. 客户端验证 timeout 范围并发送 Exec { cmd, timeout_ms }。
  2. daemon 获取当前 SSH 会话；会话已关闭时由单飞锁创建替代连接。
  3. 命令 channel 在 daemon deadline、完成、IPC 断开三者之间竞争。
  4. deadline 或客户端断开时发送 EOF/Close；只有明确收到 SSH ExitStatus 才返回成功。
  5. stdout/stderr 总量超过 8 MiB 即失败；CLI 在使用远端退出码结束前显式 flush 两个输出流。
原子上传与取消清理
  1. 拒绝空路径、超长路径和已存在的最终目标。
  2. 在同目录写入 目标.serctl-part-<128-bit random>，以便最终 rename 保持同文件系统原子性。
  3. 按 32 KiB 分块传输，核对声明字节数，并在 rename 前再次检查目标是否并发出现。
  4. 成功后 rename 到最终路径；失败时清理临时路径。
  5. 无 daemon 直连上传若被外层 timeout 取消，Drop 守卫保留 SSH 会话，在新 SFTP channel 上做最多 2 秒的后台清理，并短暂重试以覆盖 CREATE 与取消竞态。
原子下载
  1. 本地最终文件已存在时拒绝覆盖。
  2. 以 create_new 创建 .serctl-part，流式写入并累计字节数。
  3. daemon 模式核对 TransferDone.bytes；成功后 flush、sync_all 并 rename。
  4. 超时或错误时删除本地部分文件。最终目标不会被半成品覆盖。

6. CLI 参考

# 默认打开 UI
serctl
serctl ui

# 配置；密码与主口令交互输入
serctl add prod --host 192.168.5.15 --user deploy --port 22
serctl list
serctl remove prod

# 持久连接与命令
serctl up prod
serctl exec prod --timeout-secs 30 -- "uname -a; whoami"
serctl shell prod
serctl status prod
serctl down prod

# M7 evidence 工作流
serctl upload prod request.json /tmp/request.json --timeout-secs 120
serctl download prod /tmp/server-evidence.json server-evidence.json --timeout-secs 120
命令profile 规则关键语义
add省略时 default新增/更新；保留已有 pinned host key，防止无意清除信任锚
list不适用只展示 profile、明文 host 与 port，不解密用户名/密码
up/shell/status/down省略时 default前台 daemon、PTY、状态与关闭
exec必须显式指定默认 300 秒；最终进程退出码来自远端明确 ExitStatus
upload/download必须显式指定默认 300 秒；不覆盖既有目标；临时文件 + rename

SERCTL_SSH_PASS 与 SERCTL_MASTER 可用于自动化，读取后会从当前进程环境移除；但父进程、调试器或同权限观察者仍可能在读取前获得环境内容，交互输入更稳妥。

7. 桌面 UI

主机与连接

新建、编辑、删除 profile；启动、刷新和停止 daemon；显示远端地址与连接状态。

命令工作区

执行远程命令，分别展示 stdout、stderr 和退出码；网络任务不阻塞 Winit 事件循环。

目录与传输

浏览、上级目录、建目录、上传、下载；与 CLI 复用相同 client/daemon/SFTP 实现。

Bash / PTY

持续输入、Ctrl+C、Ctrl+D、清屏；daemon 不存在时可建立直连 PTY。

UI 中的“daemon active”状态现在会触发 SessionManager.current()，因此它不仅检查本机 IPC，也会在 SSH 已关闭时尝试重连。这减少假活，但同时意味着状态刷新可能受到重连阶段无硬 deadline 的影响。

8. 凭证保存安全

8.1 加密结构

数据保存形态完整性绑定
profile 名、host、port明文，支持无需解密的列表作为 AEAD AAD；篡改会导致解密失败
用户名、SSH 密码、host key 指纹ChaCha20-Poly1305 密文AEAD tag + profile/host/port AAD
主口令不保存用于 Argon2id 派生 32 字节密钥
主口令验证器独立 AEAD 密文错误主口令或篡改在写入前被拒绝
IPC token运行锁明文依赖 OS 文件权限；daemon 退出时令牌锁被删除

8.2 KDF 与输入限制

  • 算法：Argon2id v1.3；默认内存 64 MiB、迭代 3、并行度 1、输出 32 字节。
  • 加载时允许范围：内存 8–256 MiB、迭代 1–10、并行度 1–16，输出必须为 32 字节。
  • salt 必须恰好 16 字节；ChaCha20-Poly1305 nonce 必须恰好 12 字节。
  • vault 最大 16 MiB、profile 最多 10,000 条；拒绝未知 vault/record 格式版本。

8.3 文件权限与更新一致性

  • Windows：目录/文件设置 protected DACL，仅保留 owner、SYSTEM、Administrators。
  • Unix：目录 0700，文件与 socket 0600。
  • 保存使用进程间互斥锁和同目录原子替换，避免并发丢更新与崩溃截断。
  • 凭证和派生密钥使用 Zeroizing 包装，降低正常 drop 后的内存残留；这不等同于防御进程转储。
信任边界：同一用户、管理员、调试器、内存转储、键盘记录和父进程环境观察均不在防御范围内。主口令强度直接决定 vault 离线破解成本。TOFU 首次连接若遭中间人攻击，错误指纹仍可能被固定。

9. 本机 IPC

Windows

\\.\pipe\serctl-<128-bit id>；首实例防抢占，拒绝远程 pipe 客户端，忙碌/实例切换时每 10 ms 重试。

Unix

~/.serctl/run/<128-bit id>.sock；运行目录 0700、socket 0600，listener Drop 时删除路径。

协议与认证

  • 4 字节大端长度 + JSON 帧；通用最大帧 64 MiB。
  • 认证必须是第一帧，最大 4 KiB，读取 deadline 为 2 秒。
  • token 为 32 随机字节的 Base64；比较使用 constant-time equality。
  • 认证后支持 Exec、Shell、Status、Shutdown、ListDir、CreateDir、Upload、Download。
  • daemon 同时最多处理 64 个已接收 IPC 连接。

已实现 认证前帧限制可避免未认证本机连接直接声明 64 MiB 帧并触发同等分配。防御纵深 Windows Named Pipe 本体没有显式传入 owner-only security descriptor，而是依赖系统默认 pipe DACL、reject_remote_clients 和受保护锁文件中的随机 token。

11. 文件传输完整性

上传

  • 不覆盖既有远端文件；
  • 随机同目录临时路径；
  • 声明大小与实际大小核对；
  • rename 前二次检查目标；
  • 错误/timeout/取消清理残片。

下载

  • 不覆盖既有本地文件；
  • create_new 建立部分文件；
  • daemon 报告字节数与接收量核对；
  • flush + sync_all；
  • 成功后 rename，失败删除部分文件。
不承诺内容级校验：当前验证的是传输字节数、写入完成和原子可见性，没有端到端内容哈希或远端 fsync 协议。需要不可抵赖 evidence 时，应另行生成并核对 SHA-256/签名。

12. SSH 存活检测与重连

  • russh 每 30 秒发送 keepalive；最大连续无响应次数为 3。
  • SessionManager 以 RwLock<Arc<SshSession>> 保存当前连接。
  • 多个请求同时发现连接关闭时，通过 Mutex 单飞重连；首个请求认证，其余复用结果。
  • 替代连接继续使用已固定 host key，避免重连绕过主机身份校验。
  • 在途请求持有旧 Arc，替换不会把会话从其他请求下方移走。
  • status 也会检查/重连 SSH，避免仅因 IPC 存活而报告假健康。
当前缺口：SessionManager.current() 内的 DNS/TCP/SSH 连接没有显式 deadline/cancel，并且位于 exec/SFTP daemon deadline 之前。网络栈若长时间不返回，等待重连锁的请求也会一起滞留并占用最多 64 个 IPC 槽。建议为 connect/reconnect 增加独立硬 deadline，并把业务 absolute deadline 传入会话获取阶段。

14. 残余风险与建议

R1 · SSH connect/reconnect 缺少硬 deadline

中高 · 待修补

可能超过用户指定 deadline，并让并发请求等待同一重连锁、占用 daemon IPC 槽。建议以 absolute deadline 覆盖 session 获取、通道创建和业务执行，并在超时后取消连接 Future。

R2 · Named Pipe 缺少显式 owner-only DACL

中低 · 防御纵深

当前依赖默认 pipe DACL、拒绝远程客户端和 256 位 token。建议创建 Pipe 时显式传入仅 owner/SYSTEM/Administrators 的 security descriptor，并增加多用户访问测试。

R3 · 远端临时文件清理不是事务保证

低 · 已缓解

清理有 2 秒硬上限。SSH 完全不可用、权限变化或服务器故障时仍可能残留 .serctl-part-*。建议运维侧周期扫描，或未来增加可审计的残片回收命令。

R4 · TOFU 首次连接风险

固有风险

首次连接遭 MITM 时会固定错误指纹。高安全环境必须通过独立渠道预核对指纹，或增加导入 known_hosts/预置 fingerprint 的流程。

R5 · 内容证据没有加密哈希/签名

按场景

传输层检查字节数和原子性，但不提供 evidence 的内容身份或不可抵赖性。M7 等审计流程应同时拉取或计算 SHA-256，并在可信渠道记录。

R6 · Unix 与外部服务器验证空白

验证缺口

当前证据来自 Windows 与内置测试服务器。建议 CI 增加 Windows/Linux/macOS 矩阵，并以容器化 OpenSSH 运行 upload/download/timeout/reconnect E2E。

15. 运维手册

推荐启动顺序

  1. 使用长且唯一的主口令添加 profile；通过独立渠道核对首次显示的 SSH host key 指纹。
  2. 需要复用连接时运行 serctl up NAME；自动化前先用 status 验证。
  3. 为每项命令和传输设置符合任务 SLA 的 --timeout-secs，不要无条件使用 24 小时上限。
  4. M7 evidence 下载后立即计算 SHA-256，并记录 serctl commit、远端路径、时间和文件摘要。
  5. 升级跨越 IPC 迁移版本时先停止旧 loopback TCP daemon，再启动新版。

故障定位

症状含义处理
legacy daemon / legacy TCP lock正在运行不兼容旧协议停止旧进程后重新 up；不要删除仍由活进程持有的锁来绕过
authentication timed out/failed锁/token/daemon 不匹配或 IPC 无响应确认同一用户、检查 daemon 日志；正常退出后再清陈旧锁
