# serctl v1 beta acceptance matrix

<!-- normative-release: v1.0.0-beta.3 -->

This matrix is normative for `v1.0.0-beta.3`. A checkbox is evidence-backed only when its result is attached to the exact tag commit. Historical local tests, another tag, a dirty build, or a source-only platform check cannot close it.

## A. Release identity and source quality

- [ ] `scripts/Verify-ReleaseConsistency.ps1 -Tag v1.0.0-beta.3 -RequireGitTag` passes from the clean annotated tag checkout.
- [ ] Tag, workspace crates, internal path requirements, lockfile, CHANGELOG, README, user guide, architecture page and release contract all name `1.0.0-beta.3` consistently.
- [ ] A repository ruleset prevents force-update/deletion of `v*` tags; immutable releases are enabled where available, and the workflow's remote annotated-tag-object recheck is exercised. The evidence does not describe an annotated tag as inherently immovable.
- [ ] `cargo fmt --all -- --check` and `git diff --check` pass.
- [ ] Locked workspace all-target/all-feature `cargo check`, strict Clippy `-D warnings`, and serial tests pass natively on Ubuntu x86_64, Windows x86_64, macOS arm64 and macOS x86_64. Both workflows assert `runner.os`, `runner.arch` and the exact Rust host tuple before compiling, and pass that same tuple explicitly as Cargo's `--target`; an emulated, mislabeled or default-target-overridden runner cannot close a native-platform box.
- [ ] Standalone provenance build-script fixtures pass for CLI, daemon, `serctl-xfer` and `serctl-remote` on every native matrix row. The shared PowerShell driver emits `.exe` on Windows and an extensionless executable on Unix, rejects reparse-point fixture inputs/outputs and fails on either compile or fixture exit code; an Ubuntu-only invocation cannot close Windows/macOS path behavior.
- [ ] `cargo deny --locked check bans licenses sources` passes without a new exact-version exception; online `cargo audit --deny warnings` passes with current advisory data.
- [ ] CycloneDX JSON/XML SBOM generation succeeds from the tagged lockfile, and the machine-enforced SBOM gate rejects every source-only component identity in both formats. Cargo metadata is bounded strict format-version 1 with closed package/node identities, exact runtime/source-only workspace members and only known `null`/`dev`/`build` dependency kinds. JSON scans nested, primary and `metadata.tools.components`, binds Cargo purl/bom-ref names and closes dependency refs. XML is bounded, non-reparse, DTD-free CycloneDX 1.5 namespace input with equivalent component/purl/ref checks. Duplicate/case-colliding keys, wrong types, unknown dependency kinds, dangling refs and hidden source-only identities fail closed.

Local orchestration command:

```powershell
./scripts/Invoke-V1BetaLocalGate.ps1 -EvidenceDirectory C:\outside-repo\serctl-v1-gate-UNIQUE
```

The evidence directory must be a new path outside the repository and is never overwritten. Without `-EvidenceDirectory`, the gate prints results only and creates no monitored evidence file. The full command records HEAD, dirty state, Cargo/Rust toolchains, exact command, exit code and duration for every step; it fails fast on the first command failure. After the last executed step it brackets a fresh full porcelain status with two HEAD reads, records a `source_rechecked` event, and requires both final HEAD values to equal the initial HEAD plus a final clean worktree. `-Quick` skips workspace check, strict Clippy and serial tests but still runs the four standalone build-script fixtures. Quick, initially dirty, finally dirty or source-changing results exit with code 2 and are never acceptance evidence. Even a clean full local pass closes only this local source gate; it does not close exact-tag CI, real-host E2E, artifact or attestation boxes below.

- [ ] Any pre-tag Windows binaries used for controlled external probes come from `scripts/New-IsolatedCandidate.ps1`, at the new path `target/candidates/v1.0.0-beta.3-<12-character-HEAD>`. Its manifest binds a bracketed clean full `HEAD` and tree object, the random detached source worktree, explicit Cargo working directory and manifest, absolute tool identities/hashes/versions, absolute and repository-relative candidate identities, Windows volume/file identities, random root ownership, exact byte sizes, runtime modes, SHA-256 values and complete CLI/daemon/xfer version lines. All three identities share the clean commit; CLI/daemon report the storage marker, daemon reports IPC v9, and xfer reports transfer protocol v1. Original and detached tracked-source monitors reject change-and-restore races, while root-nonrecursive plus tracked-top-level monitoring excludes ignored `target` event storms; overflow and final Git rescan failures remain fail-closed. Cargo target, private source, private candidate staging and published candidate set are distinct paths. Create-new copying occurs before validation; version, size and hash come from the same pinned staging object; parent/root identities and reparse state are checked again before cleanup and move. Detached source and private build cleanup must succeed before the no-overwrite atomic publication, and no fallible recursive cleanup follows publication. `target/release` and `target/staging-v0.3` remain untouched. The PS7 and Windows PowerShell 5.1 replacement, junction, ownership, alternate-cwd, source-change, ignored-event-storm, wildcard and command-shadow tests are required before use, but prove only this Windows local construction boundary and cannot close an exact-tag, non-Windows, remote, attestation or publication gate. Non-Windows construction remains fail-closed pending a native handle-relative implementation with an actual 0755 readback.

## B. CLI, Agent and compatibility contracts

- [ ] CLI help, command names, defaults, JSON/NDJSON schema versions, exit codes and typed error categories have golden fixtures.
- [ ] Agent request/result envelopes enforce `schema_version=1`; unknown operation/field behavior fails closed, and all failure branches expose one of the documented stable `error_code` values without relying on diagnostic text.
- [ ] The exact 14-operation mapping is source-checked and tested: `status`→`daemon.status`, `exec`→`ssh.exec`, `ssh-connection-identity`→`ssh.connection-identity`, `list-dir`→`sftp.list`, `create-dir`→`sftp.write`, `transfer-push`→`transfer.write`, `transfer-pull`→`transfer.read`, `transfer-status`→`transfer.status`, `transfer-cancel`→`transfer.cancel`, `forward-local-open`→`forward.local/open`, `forward-remote-open`→`forward.remote/open`, `forward-dynamic-open`→`forward.dynamic/open`, and `forward-status/cancel`→`forward.status/cancel`. Every documented operation has both a handler and daemon issuance entry; unsupported protocol operations cannot be issued.
- [ ] All 14 Agent operations reject a missing exact scope with `agent.scope_denied` before operation-specific command/path/port/deadline validation, local file access or target probing, daemon discovery/start, listener creation or remote side effects. Transfer read/write/status/cancel and tunnel open/status/cancel remain independent and bound to the Grant profile id/generation; one scope cannot observe, initiate or affect another operation.
- [ ] Invalid JSON/shape errors do not echo serde/parser detail or rejected input; every non-scope operation failure is reduced to its fixed operation-level redacted diagnostic and stable `agent.operation_failed` category.
- [ ] `tunnel`/`grant-issue --profile-passphrase-handle`, `agent --grant-handle`, and `grant-issue --output-handle` pass native exact-tag tests on every supported client platform. Sources are mutually exclusive, reads/writes are bounded and operate only on the inherited already-open object, output requires a caller-created empty protected regular file at offset zero, and failures do not disclose the handle value or secret. The caller-retained duplicate-handle boundary is documented. The current Windows local child-inheritance E2E cannot close Unix or exact-tag boxes.
- [ ] The five Agent managed-tunnel operations prove mode/action-specific scope separation, loopback-only fixed listeners/targets, ready-before-registration, daemon ownership after the request IPC closes, bounded per-profile/global registries, profile-generation status/cancel isolation, deadline/shutdown cancellation and `unknown` for uncertain SSH cleanup. Exact-tag OpenSSH L/R/D evidence is required; mock registry tests cannot close this box.
- [ ] `ssh-connection-identity` returns only after authentication and matching host-key pin, and emits exactly profile id/generation, canonical observed host-key SHA-256, `pin_match=true`, bounded sanitized server identification, opaque transport attempt id, a daemon-generated 64-lowercase-hex `operation_context_id`, and `revision=1`. Successful `exec` and `list-dir` terminals also carry their own context and `revision=1`; missing, malformed or cross-root substituted contexts fail closed. Authentication/pre-host-key/pin-mismatch/unsafe-identification failures emit no partial identity, and endpoint, username, path, pre-banner/raw banner and credentials never appear. Source/mock OpenSSH/Dropbear tests do not replace exact-tag real-server evidence.
- [ ] Agent `transfer-pull` uses only `transfer.read`, checks scope before remote-path validation, local-target resolution/existence checks, journal access or daemon discovery, and sends only a profile-id/generation-bound SHA-256 local-target commitment rather than the raw local path. The local destination uses protected `CREATE_NEW`, handle-bound rollback and no-overwrite commit, and redacted result/error data never reveal the target. Its stdout is terminal-only; exact-tag runtime evidence must use an independently authorized `transfer-status` request for live profile-scoped progress and prove that target races never overwrite an existing destination.
- [ ] Grant-backed transfer and managed-tunnel observations carry daemon-generated 64-lowercase-hex `operation_context_id` values and positive monotonic revisions. A transfer owner generates and predeclares its opaque `transfer_id` before the blocking push/pull request. First exact status-by-id may omit context only to discover it; later exact status and every cancel supply it. Forgery, replay, rollback, cross-profile/generation reuse and restart ambiguity fail closed. One-shot daemon status, connection-identity, exec, list-dir and create-dir terminals carry distinct contexts at `revision=1`; daemon status binds an explicit no-SSH-transport marker. Formal acceptance remains blocked pending exact-tag runtime evidence.
- [ ] IPC v9 rejects the v0.3 IPC v8 descriptor/handshake and all earlier wires before a business frame; mixed CLI/daemon pairs and direct-connect fallback cannot create remote or persisted side effects.
- [ ] v0.3.0-beta.2 vault v4 upgrades in an isolated account without changing profile identity or credentials unexpectedly.
- [ ] Mixed v0.3/v1 CLI-daemon and helper pairs fail before remote or persisted side effects; no direct-connect or wire downgrade occurs.
- [ ] Whole-bundle Windows upgrade and rollback pass with hashes, descriptor ownership and daemon identity recorded. Formal runtime mode copies a fixed beta-2 vault/recovery fixture into private scratch storage, executes the matched and mixed runtime probes itself, restores and byte/ACL-verifies the complete recovery set, and only then emits a protected create-new receipt from its in-memory result; it accepts no arbitrary boolean/result JSON. The receipt's candidate CLI/daemon/xfer hashes must equal the corresponding component hashes in the hash-bound downloaded Windows/Linux platform provenance; hashes from another build of the same commit are rejected. Candidate activation rejects every predecessor/candidate component mixture and hash-only substitution. After activation, the predecessor descriptor and every predecessor Grant fail before a business frame or side effect. A failed activation restores the exact predecessor reference and bundle, while an uncertain descriptor owner or terminal state remains blocked. `scripts/Test-WholeBundleUpgradeRollbackHarness.ps1` must first pass its isolated structural self-test; that synthetic path remains `accepted=false` and cannot satisfy this runtime gate. The separate no-privilege receipt-contract self-test validates wiring only. See [the harness boundary](v1-beta-upgrade-rollback-harness.md).
- [ ] The storage-direction fixture proves `audit_seed directionally incompatible`: v1 reads a beta-2 KeyPackage with the fields absent and preserves a current package with the seed/marker present; a strict simulated v8 reader rejects the upgraded canonical package before its writer callback and leaves the input bytes/hash unchanged. This KeyPackage-only proof is insufficient because beta-2 `admin_reset_profile` can bypass KeyPackage decoding: the test must also prove that beta-2 rejects candidate top-level vault v5 before any destructive writer callback or byte change, and independently rejects a per-profile record v5 when the top level remains v4. The candidate reads both storage layers at v4 through v5, writes both at v5, and its CLI/daemon both report the exact embedded marker `vault-storage read=v4..=v5 write=v5`. The current reader rejects future unknown security fields and an initialized marker without a nonzero seed before serialization, enforcing `unknown fields must not be dropped`. The external receipt must independently mark the KeyPackage transition, both storage v4-to-v5 upgrades, beta-2 destructive-writer prevention, embedded marker, unknown-field preservation, exact pre-upgrade vault restoration, matching recovery-media restoration and ACL/owner restoration as passed. Runtime rollback after initialization requires that complete set; `binary-only rollback is forbidden`.
- [ ] The exact storage fixture source checkout is clean, its full `HEAD` starts with the common embedded candidate commit from CLI/daemon/xfer, and the candidate CLI/daemon identity grammar contains the storage marker. A fixture run from another commit, a dirty checkout, a source constant, or an unbound receipt cannot establish candidate storage compatibility.
- [ ] A v1-mutated vault is rolled back only according to the proven storage compatibility result or by restoring the `exact pre-upgrade vault backup`.

Local source evidence for this section is deliberately narrower than acceptance: the Rust tests pin top-level CLI help plus the complete recursive Clap command tree, including every subcommand's long help, defaults, directly required arguments and subcommand-required state. They also pin exit categories, Agent result NDJSON, transfer-progress NDJSON, the exact 1 MiB Agent-line EOF/LF boundary, all 14 request-to-scope mappings and scope-first typed rejection. Synthetic Windows/Linux absolute-path and secret canaries additionally prove that an otherwise wire-valid transfer event is cleared and rejected before progress/status serialization, while the complete fixed public event vocabulary remains accepted. The Agent Grant envelope and nested `OperationGrant` both reject unknown fields without echoing holder-key or rejected-field values. Local audit-chain fixtures additionally reject pending administrative records and every terminal Outcome/Administrative record that lacks a result digest, proving that refusal leaves both durable log and checkpoint bytes unchanged. A daemon registry regression separately proves that edits to serialized Grant profile/scope/budget/expiry metadata cannot expand the current-instance registration; `scripts/Test-V1BetaDocumentation.ps1` additionally requires the Agent handler set to equal the daemon issuance set and the recursive fixture to contain the exact current command-path set. These deterministic fixtures do not exercise an exact-tag binary, a live daemon, cross-version process pairs, vault upgrade, whole-bundle rollback or deployed runtime log capture, so they do not by themselves check any box above. Their results must be rerun and attached to the exact tag alongside the remaining runtime evidence.

## C. Security and lifecycle E2E

- [ ] Grant issuance process exits; after the idle window a separate process performs multiple scoped calls; expiry releases the daemon reference; post-expiry calls fail without SSH activity.
- [ ] Tampering with serialized Grant-file profile/scope/budget/expiry metadata cannot expand authority: Agent-side checks remain advisory and the daemon registry revalidates the signed root intent, holder PoP, exact profile identity/scope/budget and monotonic expiry.
- [ ] Profile name/id/generation and policy identity prevent cross-profile, same-name-recreated and stale-authority access.
- [ ] Every audit record MAC and checkpoint MAC is verified; `AuditSeed` is independent from `AuthSeed`, fresh AuthSeed/DEK rotation cannot authorize successor IPC from the predecessor, and the documented stable-seed/old-KeyPackage residual is accepted.
- [ ] Legacy zero-seed packages derive the versioned DEK-keyed, profile-id/generation-bound seed deterministically and persist it; initialized profiles with missing seed/material fail closed and never fall back to `AuthSeed`.
- [ ] Audited profile removal and destructive administrative replacement of every existing profile fail closed; Windows administrator-password plus matching-medium 2-of-2 preservation recovery remains functional and does not disclose old secrets.
- [ ] Deadline, disconnect, daemon crash and helper crash preserve `unknown` rather than inventing success, failure, deletion or commit.
- [ ] No-overwrite behavior survives target races, symlink/reparse substitution, permission denial, disk full and cleanup failure.
- [ ] `scripts/Test-WindowsMultiAccountAcl.ps1` passes on the exact Windows candidate build and emits its closed `windows_privileged_acl` details directly from that same process. Receipt mode accepts no result JSON: after successful cleanup it wraps only the in-memory gate result, binds tag/tag object/commit/release-manifest SHA-256/evidence owner, and writes a protected create-new, byte-hash-checked receipt. Its `candidate_cli_sha256` equals `serctl_cli.exe` in the downloaded Windows platform provenance. An elevated runner creates two temporary non-administrator accounts, independently proves that neither SID is a direct member of the locale-independent built-in Administrators SID and that neither secondary-logon token has the Administrator role, then has the owner create and reopen the serctl vault directory/lock. The observer proves write access to the shared parent but cannot run `serctl_cli list` against, read from or create within the owner's protected `.serctl`, and the harness verifies the exact object-owner SID plus inheritance-protected Owner Rights/SYSTEM/Administrators DACL. Missing elevation, account/logon capability, a non-administrator proof or any denial branch is a hard failure, never a skip. The explicit reparse-point branch also cannot be skipped, and cleanup passes only after the probe root and both temporary accounts are re-queried and proven absent. Failure logs withhold paths and captured command output.
- [ ] Protocol and policy parsers cover oversized, malformed, replayed, reordered and unknown fields with fuzz/property corpus evidence. The deterministic offline transfer/remote framing and policy property-style corpora, replay/order semantics and explicit limits are documented in [the parser corpus boundary](v1-beta-protocol-parser-corpus.md). The pinned, bounded Linux libFuzzer workflow supports weekly/manual development runs and is also invoked by the formal release workflow at the exact tag; both platform-bundle jobs depend on it. After all three rows pass, the reusable workflow creates one strict create-new receipt containing the tag object, commit, exact reusable-workflow ref, run id/attempt, fixed matrix/toolchain/commands, source digests and closed pass counts, then retains it as a 90-day Actions artifact. The assemble and publish jobs independently download it by artifact ID with digest verification; the existing aggregate provenance embeds the exact receipt bytes, receipt SHA-256 and artifact identity without adding a fifteenth runtime asset, and the downloaded-set verifier replays its closed-schema checks before publication. Every native matrix row resolves the independent fuzz lock with locked Cargo metadata and runs the portable boundary plus downloaded-release-set self-tests. A scheduled/manual run at another ref, local target build, workflow-source check, failed/cancelled matrix or missing/mutated receipt cannot close this box.
- [ ] Secrets and absolute local paths are absent from Agent errors, progress snapshots, release logs and audit metadata.
- [ ] Local audit tests cover keyed modification, truncation, reordering, checkpoint corruption and restart with an unmatched Grant-root intent; failures quarantine/fail closed without inventing a completed receipt, and non-Grant CLI/UI operations are not claimed as covered.
- [ ] `audit status NAME` requires the profile passphrase and exclusive profile lease, verifies the full HMAC chain/checkpoint plus an optional matching `--anchor`, and `--anchor-output` uses create-new for a bounded checkpoint file without overwriting an existing path.
- [ ] Anchor export covers no-follow regular-file checks, same-handle readback, path/parent identity, replacement-preserving rollback, FAT/exFAT inherited-ACL behavior and the documented Windows best-effort parent-directory flush limitation.
- [ ] `audit resolve-unknown NAME --acknowledge-unknown-outcome` rejects missing acknowledgement, a mismatched anchor, corrupted chain/checkpoint and profile lease contention; on valid pending Intents it only appends operation/policy/intent-bound `Unknown` outcomes and a second run is idempotent.
- [ ] The acceptance owner explicitly signs that the ledger covers OperationGrant roots only and that a manually exported anchor is not a monotonic external trust domain. Synchronized rollback of local log/checkpoint/anchor by an administrator is not detected; no release text claims audit closure or cross-snapshot rollback detection, and a separately controlled external anchor/remote transparency log remains a stable-1.0 blocker.

Local deterministic anchor tests cover bounded strict parsing, create-new, same-handle write/readback, path replacement, parent replacement during sync, cleanup-sync failure and replacement-preserving rollback. A portable injected check proves that a final parent-identity failure cannot produce success; the Unix filesystem fixture additionally rebinds the caller-visible parent while hard-linking the same anchor inode into its replacement. Success now requires a final parent-handle identity check, so matching file identity alone cannot conceal the rebind. These fixtures do not prove FAT/exFAT behavior, inherited ACLs, directory-flush behavior, removable-media custody or crash durability on the exact Windows candidate; those remain external evidence for the unchecked boxes above.

## D. External server and transfer evidence

- [ ] Windows client/daemon to a controlled Linux OpenSSH server passes exec, directory, L/R/D tunnel and SFTP fallback smoke tests.
- [ ] Any pre-authentication silent-peer failure is classified and investigated under [the SSH pre-authentication diagnostic boundary](ssh-preauth-diagnostics.md). A synchronized server-side listener/sshd/admission record, shaped from [the bounded template](ssh-preauth-server-evidence.template.json) and accepted by `scripts/Test-SshPreAuthServerEvidence.ps1`, must bind the exact later probe before the result is attributed; otherwise it remains `undetermined_path_or_listener`, and no retry/deadline/KEX change is accepted as a fix. Template validation and synthetic verifier self-tests are not real-host or release evidence.
- [ ] OpenSSH and Dropbear compatibility results are recorded separately; the external receipt binds the exact downloaded CLI/daemon/helper hashes and complete version identities, then embeds canonical protected child-receipt bytes plus recomputed SHA-256 for exactly 10 passed tests: each implementation's exec, SFTP and native result plus `OpenSSH_directory`, `OpenSSH_tunnel_local`, `OpenSSH_tunnel_remote` and `OpenSSH_tunnel_dynamic`. Each child `context_sha256` is recomputed from the exact tag/tag object/commit, runner, server and component identities. Missing, duplicated, byte/hash/context-drifted, digest-reused or mixed-component cases and unsupported extensions fail closed.
- [ ] Local-Linux2 or an equivalent controlled OpenSSH host passes 21 B, 1,298,223 B, 64 MiB and 1 GiB push/pull with no unknown partial. The runtime harness generates the fixed one-MiB repeating `byte[index] = index mod 251` payload itself and every push/pull digest equals the contract's size-specific constant; a supplied or arbitrary valid SHA-256 is rejected. The receipt's component triple equals the downloaded Windows CLI/daemon and Linux helper provenance, including an exact `helper_sha256` match to the released Linux helper bytes.
- [ ] Linux `serctl-xfer` passes descriptor/`linkat`/parent-directory fsync fault injection and 25%/75% durable-prefix resume.
- [ ] `serctl-remote`, jobs, remote protocol and policy remain source-only experimental/unshipped: workspace check/tests/strict Clippy and applicable build.rs fixtures run, while a fail-closed traversal of each shipped root (`serctl-cli`, `serctl-daemon`, `serctl-xfer`) proves that no normal or build dependency path reaches `serctl-remote`, `serctl-jobs`, `serctl-policy` or `serctl-remote-protocol`; dev-only paths do not count as runtime paths. Release build commands, staging, runtime/symbol archives, manifests, JSON/XML SBOMs and published assets contain none of those components. Agent parsing and Grant issuance reject every `job.*` kind.
- [ ] The external native-transfer receipt contains exactly eleven fault cases: 25%/75% resume; lost ACK, helper crash, `disconnect` and `daemon_restart` as `outcome_unknown` with the owned partial preserved; disk full, permission denied and target race as `transfer_failed` with the owned partial removed; `target_symlink_or_reparse` as `transfer_failed` with `no_owned_partial_created`; and unknown cleanup as `cleanup_incomplete`. Every case records no pre-ACK confirmation, target overwrite or foreign-partial deletion. The envelope binds exactly 20 passed tests after adding the eight size/direction cases and registry/window case; no case may be inferred from another.
- [ ] Every native and interop child receipt binds its canonical bytes and SHA-256 to a recomputed `context_sha256` over the exact tag, tag object, commit, runner, server and CLI/daemon/helper component identities; receipt transplant across any of those identities is rejected.
- [ ] Linux native helper proves its pinned-parent and cooperative concurrency boundary on the exact tag: the persistent intent-bound 0600 lock rejects a second conforming helper, survives crash/reopen, detects unlink/recreate before mutation, and a renamed/rebound caller-visible parent cannot redirect writes or produce `Completed`. These checks cover cooperating serctl helpers and untrusted other UIDs under the documented directory-mode/sticky assumptions only; advisory `flock` does not isolate a malicious same-UID process, and root remains outside this file-level boundary.
- [ ] SFTP reports a 2 KiB one-WRITE/STATUS window; native reports an effective 32 KiB one-chunk/one-helper-ACK window rather than the helper's larger receiver/durability limit. Confirmed bytes do not advance before the corresponding ACK.
- [ ] Transfer registry exhaustion and eviction prove 8 active/profile, 48 active/global, newest 16 terminal/profile, 256 terminal/global and at-most-15-minute retention while preserving profile-id isolation and the control-frame bound. The closed external receipt also binds the 2 KiB one-WRITE SFTP window and 32 KiB one-ACK native window and rejects any different limit or `confirmed_before_ack=true` claim.
- [ ] Native throughput is compared with same-host `scp`. Exactly five raw 64-MiB samples per backend retain elapsed microseconds, CPU basis points, RSS and RTT; p50/p95 throughput, scp p50, peak CPU/RSS, median RTT and ratio are recomputed from those samples rather than accepted as summaries. If the supported threshold is not met, native remains experimental and is excluded from the v1 support claim.

Local deterministic helper evidence now injects a failure after the no-replace link has succeeded but before post-link verification/parent-directory durability is proven. The helper returns typed `outcome_unknown` without deleting the previously durable partial or its Receiving receipt; a same-intent/token retry must revalidate the linked target, retry the parent sync, durably promote the receipt, and only then remove and sync the partial directory entry before `Completed`. The same suite distinguishes a pre-link target collision as deterministic `transfer_failed`, exercises exact 25%/75% durable-prefix resume, and checks cleanup classifications. Windows executes the portable state-machine branch, while Linux compilation covers the production descriptor-bound branch; neither result checks the Linux fault-injection boxes above until these tests run successfully from the exact tag on a native Ubuntu filesystem with the recorded kernel/filesystem identity.

The external-evidence self-tests use synthetic receipts only. The adapter validates transfer and managed-tunnel object contexts/revisions plus distinct `revision=1` contexts for daemon status, connection-identity, exec, list-dir and create-dir. The concurrent transfer owner generates its id and request streams and rejects context substitution, impossible revision ordering or late status. Verified Linux provenance binds helper identity into the local native root intent, but no exact-tag real-host HelperHello has observed that identity. A separate Windows-only owner-process vertical slice pins the PowerShell host and owner script and inherits twenty-five mutually distinct handles: one verified downloaded-set record, three components, one pre-opened receipt output and twenty purpose-checked Grants. Component identity and executable paths are derived from stable handles and Windows file identities; caller component/provenance/output paths are no longer accepted. The owner internally constructs the exact ten interop cases. Each tunnel is owned as open → status → cancel; each transfer uses distinct primary/status processes and requires status to finish before the primary terminal. The transfer source is a private create-new 21-byte payload held through a stable read-only handle; size/hash are computed from that handle and rechecked before cleanup. Every case retains the actually captured canonical child receipt as Base64 plus a recomputed SHA-256. The owner-v2 receipt separates its aggregate evidence context from ten distinct operation contexts and deterministically round-trips through the contract and external verifier, but a synthetic downloaded-set anchor deliberately leaves it unsealable. A separate native fixture owner actually supervises child workloads and recomputes eleven fault outcomes, registry/ACK limits and five native plus five scp local samples; its canonical receipt is imported only into an `unsealable_fixture_only` projection and never into formal remote slots. Every formal category therefore remains BLOCKED pending an official exact-tag record, real Grant/remote/native observations, Linux/macOS ownership and external evidence. Local PS7/Windows PowerShell 5.1 tests are not E2E receipts.

The local SSH regression boundary permits at most the existing single pre-authentication reconnect: a clean zero-peer-byte EOF before server identification may reuse only the bounded remainder of the original deadline, while a silent local deadline requires the separately reserved retry window. Received server bytes (including plaintext policy text), a parsed standard `SSH_MSG_DISCONNECT`, host-key progress, incomplete cleanup, local policy rejection or insufficient budget suppress that reconnect. A two-attempt failure must retain distinct attempt-1/attempt-2 records and derive the final phase from attempt 2. This local behavior does not satisfy the synchronized real-server evidence checkbox above and is not authority to add retries or expand the absolute deadline.

Historical predecessor evidence, not a v1 gate result: on commit `8b555f7`, Local-Linux2 completed 100,000,000-byte SFTP-fallback push and pull with matching SHA-256, no-overwrite and ACL checks (push 4.70 MB/s; pull 5.67 MB/s). Native was not exercised because the Linux helper was unavailable. This result may inform regression comparison, but it cannot check any v1 exact-tag, native-helper or typed-job box above.

## E. Tagged artifacts and publication

- [ ] The exact tag workflow—not ordinary `main` CI—repeats quality, three-platform tests and RustSec.
- [ ] Windows runtime contains a matched CLI and daemon only; PDBs are in a separate symbols archive. - [ ] Artifacts were built in the workflow's fresh `target/v1-beta-release`; neither the known mixed local `target/release` nor predecessor `target/staging-v0.3/release` contributed bytes.
- [ ] The Linux x86_64 runtime archive contains only stripped mode-0755 `serctl-xfer`; its separate symbols archive contains only non-executable mode-0644 `serctl-xfer.debug`, while provenance/governance members are also 0644. The downloaded-set verifier requires one canonical gzip member ending at physical EOF, canonical ustar, bounded headers/members/expanded bytes, rejects raw trailing/second gzip members/root directories/traversal/nesting/duplicate/case-collision/symlink/hardlink/PAX/GNU/source-only entries and binds helper/debug member digests to Linux platform provenance. `serctl-remote`, jobs, remote protocol, policy and their symbols are absent.
- [ ] The Linux helper is built on the fixed Ubuntu 22.04 release runner; `readelf` proves its maximum required GNU libc symbol version is no newer than `GLIBC_2.35`, and platform provenance records the observed maximum and supported ceiling.
- [ ] Every CLI, daemon and helper binary reports `1.0.0-beta` and the same 12-character clean tag commit. CLI and daemon identities both contain exactly `vault-storage read=v4..=v5 write=v5`; daemon additionally contains exactly `IPC v9..=v9`.
